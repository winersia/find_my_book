# 책장 스캐너 시나리오

## 한 줄

내 책장을 앱 안에 그대로 옮긴다. 칸 수를 실제 책장과 똑같이 맞추고, 칸마다 사진을 찍으면
그 칸에 꽂힌 책이 실제 순서대로 앱 책장에 들어선다.

## 이 앱이 되려는 것

기존 앱은 사진에서 책 목록을 뽑아 하나의 긴 목록에 쌓았다. 그러면 "내 책장"이 아니라
"내가 찍은 책들"이 남는다. 이 시나리오에서는 앱 화면이 실제 책장과 같은 모양을 하고,
어느 칸 몇 번째에 어떤 책이 있는지가 그대로 보인다. 책을 옮기거나 빼면 앱에서도 옮기고 뺀다.

## 용어

| 말 | 뜻 |
| --- | --- |
| 책장 (bookcase) | 가구 하나. 여러 개 만들 수 있다. |
| 칸 (slot) | 책장의 한 칸. 가로 N × 세로 M 격자로 이루어진다. |
| 책 (book) | 칸 안에 왼쪽부터 순서대로 꽂힌 한 권. |

## 화면 흐름

```
처음 실행
   │
   ├─(뒤에서) 인식 모델 내려받기 ─── 진행률 띠 ──▶ 준비 끝
   ▼
[1] 책장 설정 ──확정──▶ [2] 책장 화면 ──칸 선택──▶ [3] 칸 채우기(촬영·인식)
                            ▲                              │
                            └──────────반영────────────────┘
```

책장이 하나도 없으면 [1]이 첫 화면이다. 한 번 만든 뒤에는 [2]가 첫 화면이고,
[1]은 "책장 추가"나 "칸 수 바꾸기"로 다시 들어간다.

## [0] 앱을 처음 열었을 때

사진을 기기 밖으로 내보내지 않으려면 인식기가 브라우저 안에 있어야 한다. 그 값으로
**첫 실행에 인식 모델 17MB를 받는다.** 이 기다림을 어디에 두느냐가 첫인상을 결정한다.

**하지 않는 것**

- 시작 화면에서 막고 기다리게 하지 않는다. 받는 동안 할 일이 없으면 사람은 나간다.
- 셔터를 누른 뒤에 받기 시작하지 않는다. 찍었는데 아무 일도 안 일어나는 화면을
  수십 초 보는 것이 가장 나쁘다. 방금 한 동작과 기다림이 이어지지 않는다.
- "준비 중"만 적고 흐르는 막대를 돌리지 않는다. 숫자가 없으면 멈춘 것과 구별되지 않는다.

**하는 것**

1. 앱을 열면 **[1] 책장 설정이 곧바로 그려진다.** 모델을 기다리지 않는다.
   (`bench/flow.mjs` 에서 170ms)
2. 첫 그림이 나온 **뒤에** 뒤에서 모델을 받기 시작한다. 사람은 [1]에서 칸 수를 맞추고
   이름을 적으며 10~30초를 쓴다. 그 시간이 내려받기 시간이다.
   셔터를 누를 때는 대개 이미 준비가 끝나 있다.
3. 받는 동안 헤더 아래 **얇은 띠 하나**가 진행률을 보여 준다.
   - `글자 인식 준비 중 · 3.4 / 17.4MB` 와 `19%`, 그리고 채워지는 막대.
   - **받은 바이트로 잰 진짜 숫자다.** 서버가 gzip 으로 보내면 `content-length` 는
     압축된 크기라 분모로 쓸 수 없어, 우리가 배포하는 파일의 크기를 상수로 둔다
     (`src/lib/ppocr.ts` 의 `MODEL_BYTES`, `scripts/fetch-ppocr.mjs` 가 맞는지 확인한다).
   - 아래 한 줄로 **왜 기다리는지**를 한 번만 말한다:
     "처음 한 번만 받아요. 사진은 기기 밖으로 나가지 않아요."
     "매번 이러나?"와 "내 사진은 어디 가나?"가 이탈을 부르는 두 가지 의문이다.
4. 띠는 **아무것도 막지 않는다.** 덮개도 모달도 아니고 버튼을 가리지도 않는다.
   받는 중에도 책장을 만들고 칸을 고를 수 있다.
5. **0.6초 안에 끝나면 띠를 띄우지 않는다.** 다시 들어온 사람은 브라우저 캐시에서
   꺼내 쓰므로 금방 끝난다. 그때 번쩍이는 띠는 알림이 아니라 소음이다.
6. 끝나면 `글자 인식 준비 끝` 을 2.4초만 보이고 **스스로 사라진다.** 한 방문에 한 번만
   말한다. 화면을 옮겨 다닐 때마다 다시 알리지 않는다.
7. 실패하면 띠가 남아 이유를 말하고 **[다시 시도]** 를 준다. 이것만은 저절로 사라지지 않는다.
8. **데이터 절약 모드**(`navigator.connection.saveData`)이거나 2G면 미리 받지 않는다.
   그때는 셔터를 누를 때 받고, 진행 화면에 같은 퍼센트 막대를 보여 준다.
   받는 이유가 분명한 순간이라 기다림이 납득된다.

미리 받아 두므로 **[3]의 진행 화면에서 모델을 기다리는 일은 드물다.** 그래도 오게 되면
(절약 모드, 첫 화면을 금방 지나친 경우) 같은 문구와 같은 퍼센트 막대를 쓴다.

## [1] 책장 설정 화면

- **왼쪽**: 책장 이름, 가로 칸 수, 세로 칸 수를 조절한다.
  - 숫자는 `−` / `+` 버튼과 직접 입력 둘 다 된다.
  - 기본값은 **가로 8 × 세로 2**.
  - 범위는 가로 1~12, 세로 1~8. 실제 책장을 넘어서는 값은 화면에서 다루기 어렵다.
- **오른쪽**: 조절한 숫자만큼 칸이 그려진 미리보기. 숫자를 바꾸면 즉시 따라 바뀐다.
- 아래 **[이 책장 만들기]** 를 누르면 확정하고 [2]로 간다.
- 이미 있는 책장의 칸 수를 바꾸는 경우:
  - 칸이 늘면 새 칸은 비어 있다.
  - 칸이 줄어 사라지는 칸에 책이 있으면, 확정 전에 몇 권이 지워지는지 알리고 되묻는다.

## [2] 책장 화면 (기본 화면)

- 책장 그림이 **늘 보인다**. 칸은 격자로, 각 칸에는 꽂힌 책이 책등 모양으로 그려진다.
  - 책등은 인식할 때 사진에서 뽑은 **대표 색**과 **두께 비율**로 그린다. 실제 책장과 닮아 보인다.
  - 책이 없는 칸은 비어 있다는 표시와 함께 누르라고 안내한다.
- 칸을 누르면 선택된다. 선택한 칸은 아래에서 다룬다.
  - 선택한 칸에 책이 없으면: **[이 칸 촬영하기]**
  - 책이 있으면: 책 목록 + **[다시 찍기]** + 편집 도구
- 위쪽에 책장 이름과 전체 권수, 책장이 여럿이면 책장 전환이 있다.

## [3] 칸 채우기 (촬영과 인식)

1. 칸을 고르고 [이 칸 촬영하기]를 누른다.
2. 카메라가 열린다. 그 칸만 화면에 꽉 차게 찍는다. (갤러리에서 고를 수도 있다)
   - 안내 틀이 "칸을 꽉 채워 주세요 · 한 번에 n권까지"라고 알려 준다. n은 이 기기의
     카메라가 실제로 주는 가로 화소로 계산한다. 기종마다 다르다.
3. 인식이 끝나면 결과를 **왼쪽부터 순서대로** 보여 준다.
   - 기다리는 동안 **잴 수 있는 것은 숫자로 보여 준다.** 모델 내려받기는 받은 바이트로,
     책등 읽기는 `12/46` 과 남은 초로 잰다. 잴 것이 없는 "책등을 찾는 중"만 흐르는 막대다.
     흐르는 막대는 멈춘 화면과 구별되지 않으니 꼭 필요한 곳에만 쓴다.
   - **셔터를 누르면 곧바로(0.3초 안에) 진행 화면이 뜬다.** 인식 추론은 워커에서 돌고,
     무거운 단계 사이와 책등 한 줄마다 화면을 그릴 틈을 준다. 예전에는 인식이 메인 스레드를
     쉬지 않고 붙잡아, 휴대폰에서 셔터 뒤 몇 분 동안 화면이 그대로였다 (`bench/mobile.mjs`).
   - 남은 시간은 실제로 읽은 속도로 어림잡는다. 기기마다 열 배 가까이 다르다.
   - 책 정보(표지·ISBN)는 결과를 먼저 보여 준 뒤 뒤에서 채운다. 손으로 고친 제목은
     덮지 않는다. 다 채워지기 전에 넣으면 그 책들은 책 정보 없이 들어간다.
4. **[이 칸에 넣기]** 를 누르면 그 칸의 내용이 결과로 **교체**된다.
   - 이미 책이 있던 칸이면 "n권을 새로 찍은 m권으로 바꿉니다"라고 알린다.
   - 취소하면 칸은 그대로다.

### 나눠 찍기

얇은 책이 빽빽한 칸은 한 번에 담을수록 책등 하나가 차지하는 화소가 줄어든다.
정확도를 결정하는 것은 권수가 아니라 **책등 하나에 실린 화소 수**다.
찍은 뒤 책등이 바닥(40px)을 밑돌면 결과 화면에서 먼저 **한 칸만 꽉 차게 다시 찍기**를
권하고, 한 장에 안 들어올 때 쓰라고 **[이어서 찍기]** 를 함께 안내한다.
나눠 찍는다고 제목이 더 잘 읽히지는 않았다. 40px은 목표가 아니라 바닥이다.
이때 "책등이 34px로 얇아요. 이 카메라는 한 장에 20권까지예요. 3번에 나눠 찍어 주세요"처럼
**잰 값과 몇 등분해야 하는지**를 같이 알려 준다.

1. 결과 화면에서 [이어서 찍기]를 누르면 카메라가 다시 열린다.
2. 방금 찍은 곳 **다음부터**, 한두 권만 겹치게 찍는다. 그만큼 더 가까이 가게 된다.
3. 새 결과가 앞 결과 **뒤에 이어 붙는다.** 이음매에서 제목이 똑같은 책은 조용히 한 권만 남긴다.
4. 원하는 만큼 반복한 뒤 [이 칸에 넣기]를 누른다.

교체가 아니라 **이어 붙이기**인 것이 [처음부터 다시]와 다른 점이다.
순서는 찍은 순서를 그대로 따른다. 왼쪽부터 찍으면 칸에서도 왼쪽부터 들어간다.

### 인식 결과를 칸에 넣는 규칙

- **순서를 지킨다.** 사진 왼쪽에 있던 책이 칸에서도 왼쪽이다.
- **권수를 지킨다.** 같은 제목이 두 번 읽혀도 두 권으로 넣는다. 실제로 같은 책이 두 권
  꽂혀 있을 수 있다. (기존 앱은 여기서 중복을 합쳐 권수가 달라졌다)
- **못 읽은 것도 자리를 지킨다.** 제목을 못 읽은 책등은 "제목 미상"으로 자리만 잡아 둔다.
  실제 권수와 순서가 맞아야 나중에 손으로 고칠 수 있다.
  - 글자가 안 보이는 책(그늘진 책등, 뒤로 물러선 책)도 책등 경계로 찾아 빈칸 한 권으로 넣는다.
    빠뜨리면 그 뒤 책이 한 칸씩 당겨져 순서가 줄줄이 틀린다.
- **확신이 낮은 제목은 넣되, 사용자가 하나씩 확인해야 칸에 넣을 수 있다.** 확신 85% 미만이거나
  제목을 못 읽은 책(글자 없는 책 포함)은 결과 화면에서 눈에 띄게 표시하고, 인식기가 실제로 읽은
  책등 그림을 제목칸 아래에 붙여 견줘 보게 한다. [맞아요]를 누르거나 제목을 고쳐 쓰거나 [빼기]를
  하면 확인된다. 확인 안 된 책이 남아 있으면 [넣기] 대신 "확인 n권 남음 · 다음 책 보기"가 나와
  다음 확인할 책으로 데려간다. 확인한 책은 칸에 넣은 뒤 "확인 필요"로 다시 뜨지 않는다.
  - 85%: 실제 책장 사진 31권에서 바르게 읽은 제목은 모두 88% 이상, 틀린 것은 69~80% 였다.
  - 책등 그림은 결과 화면에서만 쓰고 저장하지 않는다.
  - 제목이 빈 책은 책 정보(Open Library)로 채우지 않는다.
- **사용자가 확인하거나 고친 제목은 기억해 두었다가, 같은 책을 다시 찍으면 채운다.** 인식기가 끝내
  못 읽는 책(장식 글꼴, 아주 작은 글씨)도 한 번 고쳐 주면 다음부터는 묻지 않는다.
  - 알아보는 단서는 두 가지다. 인식기가 읽은 글자(같은 책등은 다시 찍어도 비슷하게 틀린다)와
    책등을 아주 작게 줄인 모양 지문(24×6 색 무늬). 같은 시리즈 책은 무늬가 닮아서 모양만으로는
    믿지 않는다. 글자와 모양이 둘 다 맞으면 확인 없이 넘기고, 하나만 맞으면 제목은 채우되 확인을 받는다.
  - 확인이 필요한 책에만 쓴다. 인식기가 잘 읽은 책은 그대로 둔다.
  - 기억으로 채운 제목에는 "기억한 제목" 표시가 붙는다.
  - 기억은 이 기기의 localStorage 에만 둔다 (제목, 읽은 글자, 모양 지문). 사진은 남기지 않는다.
    "책장 설정과 내보내기"의 [기억한 제목 지우기]로 지운다. 책장의 책은 그대로다.
- **책등 위아래 끝의 라벨은 제목이 아니다.** 시리즈·출판사 표기(ChildApple, NATIONAL GEOGRAPHIC,
  비룡소)는 책등 끝에 있고 제목은 가운데쯤에 있다. 가운데 구역의 줄만 제목 후보로 본다.
  제목 줄을 못 읽었으면 라벨로 채우지 않고 비워 둔다.
- 신뢰도가 낮은 책은 화면에서 흐리게 보이고 "확인 필요" 표시가 붙는다.
- **제목 앞뒤의 군더더기는 떼어낸다.** 옆 책 그림자가 "UN", "55덱" 같은 조각으로 읽히는 일이
  잦다. 짧고 확신이 낮은 조각이 제목 끝에 붙어 있으면 버린다. 가운데 글자는 건드리지 않는다.
- **세로로 쌓은 글자는 띄어쓰기를 버린다.** 쌓인 글자에는 띄어쓰기가 없으므로 모델이 음절
  사이에 넣은 공백은 모두 군더더기다 ("어 린 왕자" → "어린왕자").

## 멈춤과 로딩 표시

**앱이 응답하지 못하는 순간에는 반드시 로딩 표시가 돈다.** 표시 없이 멈추면 사용자는
앱이 죽은 줄 알고 나간다.

- 멈춘 동안에는 자바스크립트가 아무것도 그리지 못한다. 그래서 무거운 일을 **시작하기 전에**
  로딩 표시를 세우고, 그것이 화면에 한 번 그려진 뒤에 일을 시작한다 (`src/lib/busy.ts`).
- 로딩 표시는 CSS 회전·투명도만으로 움직인다. 이 애니메이션은 브라우저가 메인 스레드와 따로
  돌려서 앱이 멈춘 동안에도 돈다. 0.3초 안에 끝나는 일에는 깜빡이지 않도록 0.3초 뒤에 나타난다.
- 떠 있는 동안에는 탭을 막는다. 멈춘 앱에 쌓인 탭이 한꺼번에 처리되면 셔터가 두 번 눌린다.

| 순간 | 표시 |
| --- | --- |
| 앱 코드를 받는 동안 | `index.html` 에 직접 적은 스플래시 "책장 스캐너를 여는 중" |
| 셔터를 누른 뒤 사진을 줄이는 동안 | 덮개 "사진 준비 중" |
| 갤러리 사진을 풀고 줄이는 동안 | 덮개 "사진 여는 중" |
| 인식 중 (단계 사이 몇 초씩 멈춤) | 진행 화면의 단계 이름 옆 스피너 |

덮개는 사진을 넘기는 데까지만 쓴다. 인식은 진행 화면이 맡고, 덮개가 남으면 그만두기를 가린다.
인식 추론 자체는 워커에서 돌아 화면을 붙잡지 않는다.

## 칸 편집

선택한 칸에서 다음을 할 수 있다.

| 하는 일 | 방법 |
| --- | --- |
| 제목·저자 고치기 | 글자를 눌러 바로 고친다 |
| 다르게 읽기 | 인식이 남긴 다른 후보로 바꾼다 |
| 순서 바꾸기 | 책마다 `←` `→` 로 한 칸씩 옮긴다 |
| 책 빼기 | `×` 를 누른다 |
| 책 넣기 | [책 추가]로 빈 책을 만들고 제목을 적는다 |
| 다른 칸으로 옮기기 | [옮기기]를 누르고 옮길 칸을 고른다 |
| 칸 비우기 | [칸 비우기] |

모든 변경은 즉시 저장된다. 저장 위치는 브라우저 localStorage다.

## 여러 책장

- 책장을 여러 개 만들 수 있다 (거실, 서재 등).
- 위쪽 전환기로 책장을 바꾼다. 각 책장은 자기 칸 수와 내용을 가진다.
- 책장 이름 바꾸기, 삭제가 가능하다. 삭제는 되묻는다.

## 데이터 모델

```ts
interface Bookcase {
  id: string;
  name: string;          // "거실 책장"
  columns: number;       // 가로 칸 수 (기본 8)
  rows: number;          // 세로 칸 수 (기본 2)
  slots: Slot[];         // 길이 rows*columns, 왼쪽 위부터 행 우선
  createdAt: string;
}

interface Slot {
  books: ShelfBook[];    // 왼쪽부터의 순서
  photo?: string;        // 마지막으로 찍은 사진 (작은 미리보기)
  scannedAt?: string;
}

interface ShelfBook {
  id: string;
  title: string;         // 비어 있으면 "제목 미상"으로 보여 준다
  author: string;
  spineText: string;     // OCR 원문
  alternatives: string[];// 다른 방향/모델로 읽은 후보
  confidence: number;    // 0~1
  color?: string;        // 책등 대표 색 (#rrggbb)
  widthRatio?: number;   // 칸 안에서 차지하는 두께 비율
  match?: BookMatch;     // Open Library 보강
}
```

## 저장과 내보내기

- 책장 전체가 localStorage에 저장된다. 앱을 다시 열어도 그대로다.
- CSV로 내보내면 `책장, 칸(행/열), 순서, 제목, 저자, 책등 원문, 신뢰도` 를 담는다.
  칸과 순서가 들어가야 "어디 몇 번째 책"인지 남는다.
- JSON으로 내보내면 위 데이터 모델 그대로 나간다.

## 엣지 케이스

| 상황 | 처리 |
| --- | --- |
| 칸을 고르지 않고 촬영 | 촬영 버튼이 나오지 않는다. 칸부터 고르게 안내한다. |
| 인식 결과가 0권 | "책을 찾지 못했다"고 알리고 칸은 그대로 둔다. 다시 찍기를 권한다. |
| 한 사진에 여러 칸이 찍힘 | 책이 꽂힌 행 구간을 먼저 잘라 한 줄만 본다. 한 칸씩 찍으라고 안내한다. |
| 책등이 너무 얇게 잡힘 | 제목이 뭉개진다. 잰 굵기와 몇 등분할지를 알려 주고 [이어서 찍기]를 권한다. |

| 나눠 찍다가 겹침 | 이음매에서 제목이 똑같은 책만 한 권으로 합친다. 못 읽은 책은 손대지 않는다. |
| 칸 수를 줄여 책이 사라짐 | 몇 권이 지워지는지 알리고 되묻는다. |
| 카메라를 못 씀 | 갤러리 사진 선택으로 대체한다. |
| 인식 모델을 못 받음 | 준비 띠가 남아 실패를 알리고 [다시 시도]를 준다. 책장 만들기는 그대로 된다. |
| 데이터 절약 모드 | 미리 받지 않는다. 셔터를 누를 때 받고 같은 퍼센트 막대를 보여 준다. |
| 준비가 끝나기 전에 셔터를 누름 | 진행 화면에서 같은 퍼센트 막대로 이어 보여 준다. 같은 내려받기를 기다린다. |
| 제목에 오탈자가 남음 | Open Library는 낱말 검색이라 오탈자를 고치지 못한다. 화면에서 직접 고친다. |

## 완료 기준

이 시나리오는 다음이 실제로 동작할 때 완료로 본다. `bench/flow.mjs` 가 이 목록을 그대로 확인한다.
13~16번은 크로미움의 망 속도를 2MB/s 로 낮춰, 실제 휴대폰에서 겪는 몇 초를 만들어 놓고 본다.

1. 처음 열면 책장 설정 화면이 나오고 기본이 8×2다.
2. 가로·세로 숫자를 바꾸면 오른쪽 미리보기 칸 수가 따라 바뀐다.
3. 확정하면 책장 화면이 뜨고 책장 그림이 늘 보인다.
4. 칸을 누르면 그 칸이 선택된다.
5. 선택한 칸을 촬영하면 인식 결과가 순서대로 나온다.
6. 칸에 넣으면 그 칸에만 책이 들어가고, 권수와 순서가 인식 결과와 같다.
7. 책 순서를 바꾸면 책장 그림에도 반영된다.
8. 책을 빼거나 넣을 수 있다.
9. 같은 칸을 다시 찍으면 내용이 교체된다.
9-2. [이어서 찍기]로 나눠 찍으면 앞 결과 뒤에 이어 붙고, 이음매의 같은 제목은 한 권만 남는다.
9-3. 촬영 안내에 이 기기의 카메라 해상도로 계산한 "한 번에 n권까지"가 나온다.
10. 다른 칸을 찍어도 앞 칸은 그대로다.
11. 책장을 하나 더 만들 수 있고, 각자 내용을 가진다.
12. 앱을 다시 열어도 책장, 칸, 순서가 그대로다.
13. 모델을 받는 동안에도 첫 화면이 곧바로 그려진다.
14. 받는 동안 진행률이 **숫자로** 보이고, 그 숫자가 움직인다.
15. 받는 동안에도 책장을 만들고 칸을 고를 수 있다 (아무것도 막지 않는다).
16. 준비가 끝나면 진행 표시가 스스로 사라진다.
18. 왼쪽부터 자리마다 실제 책과 순서·권수가 맞는다 (`bench/order.mjs`, 실제 책장 사진 29권).
19. 확신이 낮은 책이 남아 있으면 칸에 넣을 수 없고, 하나씩 확인하면 넣을 수 있다 (`bench/review.mjs`).
20. 확인한 책장을 다시 찍으면 기억한 제목이 채워져 덜 묻고, 엉뚱한 책에 채우지 않는다.
    기억을 지우면 다시 처음처럼 묻는다 (`bench/review.mjs`, 다시 찍은 것처럼 바꾼 사진은 `bench/memory.mjs`).
17. 앱이 0.5초 넘게 멈추는 동안에는 늘 로딩 표시가 떠 있다. 휴대폰 조건(CPU 4배 감속)에서
    셔터와 갤러리 두 경로를 `bench/mobile.mjs` 로 잰다: 표시 없이 멈춘 구간 0번.
