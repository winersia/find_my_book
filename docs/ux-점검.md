# UX 점검과 개선

체크리스트를 앱에 직접 대 보고 고친 기록. 화면은 실제로 띄워 캡처했고, 기준은 **모바일 폭
420px**이다. 이 앱은 책장 앞에 서서 휴대폰으로 쓰는 물건이라 좁은 화면이 기본이다.

## 무엇을 어떻게 봤는가

`bench/flow.mjs`로 앱을 실제 조작하며 화면을 단계별로 캡처했다. 설정, 빈 책장, 칸 선택,
카메라, 인식 중, 결과 확인, 채워진 칸의 일곱 장면을 모바일과 데스크톱 폭에서 봤다.

느낌으로 판단하지 않으려고 숫자 하나를 정했다. **앱을 열고 첫 칸이 채워질 때까지 몇 번
누르는가.** flow 테스트가 매번 이 값을 찍는다.

| | 개선 전 | 개선 후 |
| --- | --- | --- |
| 첫 칸을 채우기까지 누른 횟수 | 8번 | **7번** |
| 화면에 적힌 설명 글자 수 | 477자 | **102자** |

(누름 횟수에는 테스트가 칸 수를 8→6으로 바꾸는 두 번이 포함돼 있다. 순수 흐름은 6번 → **5번**.)

두 숫자 모두 테스트가 매번 찍는다. `node bench/flow.mjs`, `node bench/copy.mjs`.

## 1. 사용자 의도와 행동

**문제**

- 첫 화면에 이 앱이 무엇을 하는 물건인지 한 줄도 없었다. "책장 만들기"와 숫자 두 개뿐이라,
  왜 칸 수를 맞춰야 하는지 알 수 없었다.
- "이 칸 촬영하기"를 눌러도 카메라가 켜지지 않고 "카메라 켜기"를 한 번 더 눌러야 했다.
  누른 사람의 예상과 다르다.
- 첫 촬영에서 4MB를 내려받느라 오래 걸리는데 아무 설명이 없었다. 멈춘 줄 안다.

**고침**

- 첫 화면 제목을 "내 책장을 앱에 옮겨요"로 바꾸고 1·2·3 단계를 적었다.
- 촬영 화면을 열면 카메라가 바로 켜진다 (한 단계 삭제).
- 처음 인식할 때만 "처음 한 번만 약 4MB를 내려받습니다"를 미리 알린다.

## 2. 프로세스와 사용성

**문제**

- 인식이 25초쯤 걸리는데 **멈출 방법이 없었다**. 닫기(×)를 눌러도 뒤에서 계속 돌았다.
- 잘못 읽은 제목을 **넣기 전에는 못 고쳤다**. 일단 칸에 넣고 나서 다시 고쳐야 했다.
- 책 빼기·칸 비우기·다시 찍기가 **되돌릴 수 없었다**. 잘못 누르면 끝이다.
- 설정 화면에서 확정 버튼이 미리보기보다 **위**에 있었다. 결과를 보기 전에 확정을 먼저 만난다.
- CSV·JSON·책장 지우기가 첫 화면에 나란히 있었다. 책 한 권 없는데 내보내기부터 보인다.

**고침**

- 인식 중 **그만두기** 버튼. 실제로 중단된다 (AbortSignal을 인식 루프에 연결).
- 결과 화면에서 제목을 바로 고치고, 책이 아닌 것은 **빼기**로 제외한 뒤 넣는다.
- 책 빼기·칸 비우기·칸 교체는 **되돌리기**가 딸린 알림을 띄운다. 확인 창으로 막는 대신
  일단 해 주고 되돌릴 길을 남겼다. 흐름이 끊기지 않는다.
- 모바일에서 미리보기를 조절기 **위**로 올리고 확정 버튼을 맨 아래로 내렸다.
  조절 → 결과 확인 → 확정 순서가 된다.
- 부가 기능은 "책장 설정과 내보내기"로 접었다. 책장 지우기는 그 안에서도 따로 떼어 놓았다.

## 3. 시각 디자인

**문제**

- 빈 칸마다 "비어 있음"이 들어가 좁은 화면에서 **"비어 있"/"을"로 줄바꿈되어 16번 반복**됐다.
- 셔터가 다른 버튼들과 같은 크기로 왼쪽 끝에 있었다. 사진 앱을 쓰던 손이 찾지 못한다.
- 찍는 법을 글로만 안내했다.
- 순서 바꾸기 버튼 등이 작아 손가락으로 누르기 빠듯했다.

**고침**

- 빈 칸은 글자 대신 **+**. 누르면 강조된다.
- 셔터를 **아래 가운데 큰 원형**으로. 사진 앱의 자리와 모양을 그대로 따랐다.
- 카메라 화면에 **점선 틀**과 "이 틀에 칸을 꽉 채워 주세요". 글 대신 보여 준다.
- 터치 영역을 40~44px로 키웠다.
- 책장은 폭에 맞춰 줄어들어 **한눈에 다 들어온다**. 칸이 34px보다 좁아질 때만 가로로 넘긴다.

## 4. 문구

**문제**

- 칸 이름이 "1층 1번째 칸"이었다. 책장에서 "1층"은 맨 아래를 뜻하기도 해 화면과 어긋난다.
- "내 책장을(를) 만들었어요" — 조사 처리가 없었다.
- "다르게 읽기"가 무엇을 하는 버튼인지 예측하기 어려웠다.
- 인식 중 문구가 "글자 인식 모델 준비 중"이었다. 모델이 무엇인지 사용자는 모른다.

**고침**

- "1번째 줄 1번째 칸". 설정 화면에서 쓴 "줄"과 "칸"을 그대로 쓰고, 화면에 보이는 대로
  위에서부터 센다.
- 이름 끝 글자를 보고 을/를, 은/는을 고른다.
- "'Clean Code'로 바꾸기"처럼 바뀔 결과를 버튼에 적는다.
- "읽을 준비를 하고 있어요" → "책등을 읽는 중 3/5 · 약 6초 남음".

## 5. 데이터와 측정

**문제**

- 좋아졌다는 근거가 없었다. 전부 눈대중이었다.

**고침**

- flow 테스트가 매번 **첫 칸을 채우기까지의 누름 횟수와 시간**을 찍는다. 8번 → 7번.
- 인식 품질은 `bench/run.mjs`가 따로 잰다 (찾은 권수, 글자까지 정확한 권수, 글자 오류율).
- 나쁜 결과도 남긴다. 아래 "아직 못 고친 것"이 그 자리다.

## 두 번째 점검: 설명 줄이기

첫 점검에서 안내를 여럿 **더했다**. 다시 보니 화면이 이미 보여 주는 것을 글로 되풀이하는
곳이 많았다. 기준을 하나 세우고 걷어냈다.

> **화면이 이미 보여 주는 것은 글로 다시 말하지 않는다.**

`bench/copy.mjs`가 화면마다 "읽어야 알 수 있는 글"의 글자 수를 센다. 버튼 이름과
데이터(제목, 권수)는 빼고 센다.

| 화면 | 전 | 후 | 무엇을 뺐나 |
| --- | --- | --- | --- |
| 설정 | 81자 | 22자 | 1·2·3 단계 목록, "8칸 × 2줄 = 모두 16칸", "이런 모양이 됩니다" |
| 책장 | 48자 | 17자 | 한 문장으로. 책이 들어찬 뒤에는 아예 없앰 |
| 빈 칸 | 45자 | 0자 | "이 칸만 꽉 차게 찍으면…" — 바로 위에 촬영 버튼이 있다 |
| 카메라 | 139자 | 56자 | 상단 안내 — 화면의 점선 틀이 같은 말을 하고 있었다 |
| 인식 중 | 77자 | 0자 | 개인정보 문구를 첫 실행 공지로 옮김 |
| 결과 | 87자 | 7자 | "고치거나 뺄 수 있습니다" — 입력칸과 빼기 버튼이 보인다 |
| **합계** | **477자** | **102자** | |

측정하면서 드러난 것도 있다. 빈 칸 안내 한 문장이 촬영·인식·결과 화면 **뒤에 계속 겹쳐**
네 번 세어졌다. 그 문장을 지우자 함께 사라졌다.

글자 말고도 같이 걷어낸 것.

- **잘 읽힌 책에 붙던 "다른 후보로 바꾸기"**. 거꾸로 읽은 쓰레기를 권하고 있었다.
  확인이 필요한 책에만 보여 준다.
- **책등 원문 배지**도 같은 기준으로 옮겼다. 제대로 읽었으면 원문을 볼 이유가 없다.
- **ISBN 숫자 13자리**. 화면에서 할 일이 없다. CSV 에는 그대로 있다.
- **"카메라 끄기"**. 시트를 닫으면 꺼진다. 고를 이유가 없는 선택지였다.
- **셔터의 "촬영" 글자**. 큰 원형 셔터는 사진 앱에서 이미 배운 모양이다.
  준비되지 않았을 때만 "준비 중…"을 띄운다.

남긴 것은 **화면을 봐서는 알 수 없는 것들**이다. 처음 한 번 4MB를 받는다는 사실,
사진이 기기 밖으로 나가지 않는다는 사실, 칸 수를 실제 책장과 맞춰야 한다는 사실.

## 아직 못 고친 것

- **인식 25초는 여전히 길다.** 취소와 진행 표시로 견딜 만하게 만들었을 뿐, 짧게 만들지는
  못했다. 책등마다 두 방향을 읽는 구조라 권수에 비례해 늘어난다.
- **실제 사용자에게 물어본 적이 없다.** 위의 모든 판단은 체크리스트와 화면을 놓고 내린
  것이고, 실제 책장 앞에서 쓴 사람의 행동은 보지 못했다. 체크리스트 5번이 경계하는 바로 그
  상태다. 숫자는 "누름 횟수" 하나뿐이고, 그마저 자동 조작 기준이다.
- **칸이 많은 책장(12칸×8줄)은 모바일에서 여전히 빽빽하다.** 칸을 눌러야 내용을 볼 수 있다.
- 책장 그림의 책등 글자는 작아서 거의 읽히지 않는다. 지금은 색과 두께로 "내 책장 같음"을
  만들고, 제목은 칸을 눌러 확인하게 되어 있다.
