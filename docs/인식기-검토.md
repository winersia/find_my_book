# 이미지 속 한국어 인식: 선택지 전부 검토

tesseract.js로 책등 제목을 읽는 것이 한계에 닿아서, 쓸 수 있는 방법을 전부 모아 따져 봤다.
**측정한 것과 자료만 본 것을 구분해 적는다.**

## 재는 방법

실제 책장 사진 한 장(2576×1932, 43권)에서 책등 46개를 잘라 두고, 손으로 적은 정답 40개와
대본다. 제목이 읽기 결과 어딘가에 거의 그대로 들어 있으면 찾은 것으로 센다
(부분 일치 편집 거리, `bench/score.mjs`). 같은 크롭을 쓰므로 **인식기만의 차이**가 나온다.

| | 거의 정확 90%+ | 고치면 됨 70~90% | 비슷은 함 40~70% | 못 읽음 |
| --- | --- | --- | --- | --- |
| tesseract.js (지금) | 6 | 6 | 11 | 17 |
| **PaddleOCR 한국어** | **9** | **8** | 6 | 17 |

쓸 만한 제목(70% 이상)이 **12 → 17권**. 띄어쓰기도 살아난다.

```
tesseract   고푼늑대와잘난척타조
PaddleOCR   배고받 누대와 잘난 척 타조
tesseract   (못 읽음)                    ← 누가 먼저 먹어야 할까
PaddleOCR   누가먼저 먹어야 할까
tesseract   (못 읽음)                    ← 딜런의 병원 놀이
PaddleOCR   딜런의 병원놀이
```

`못 읽음 17권`은 양쪽 다 그대로다. 제목이 아주 작거나, 밴드가 벽·빈자리인 경우다.

## 1. 지금 쓰는 것을 더 짜내기 — 전부 실패

| 시도 | 결과 |
| --- | --- |
| 크롭 확대 1.5 / 3 / 6배 | 달라지지 않음. 스케일 문제가 아니다 |
| `tessdata_best` float 모델 | **tesseract.js가 지원하지 않는다.** SIMD 코어에서도 `DotProductSSE` 없음으로 죽는다. CDN에 `_best_int`(양자화본)만 있는 이유이고, 우리는 이미 그걸 쓴다 |
| 대비 정규화 | 실제 12→11권, 합성 퇴행 |
| 흑백 반전 (자동 판단) | 실제 12→13권, 합성 퇴행 |
| 흑백 반전 (양쪽 읽고 선택) | 실제 12권 그대로, 시간만 2배 |

손으로 정확히 자른 책등을 분할 없이 넣어도(`bench/spine.mjs`) 세 방향 모두 0점이 나온다.
**분할이 아니라 인식기가 한계다.**

## 2. 브라우저에서 도는 다른 인식기

### PaddleOCR PP-OCRv5 한국어 — 재 봤고, 이긴다

`PaddlePaddle/korean_PP-OCRv5_mobile_rec_onnx` (공식 ONNX, 12.8MB)를 onnxruntime-web으로
돌렸다. 위 표가 그 결과다. 재현 방법은 아래 "직접 재보기"에.

- **키 없음, 사진이 기기 밖으로 나가지 않음.** 지금 앱의 약속을 그대로 지킨다
- 모델이 만든 쪽 기준 한국어 정확도 88% (줄 단위, 한 글자만 틀려도 오답)
- 깨끗한 한 줄로 시험하면 `네 기분은 어떤 색깔이니` 를 그대로 읽는다 (0.9)
- 책등 한 장에 세 방향 읽어 1.1~1.4초. 46권이면 1분 안팎으로, 지금(46초)과 비슷한 수준

치를 값:
- 모델 12.8MB + onnxruntime-web 런타임(wasm) 약 10MB가 첫 실행에 더 붙는다.
  지금은 tesseract 언어데이터 약 4MB + wasm 코어 약 4MB다
- 인식 코드를 새로 쓴다. 책등 자르기·방향 고르기·제목 줄 고르기는 그대로 쓸 수 있다
- PaddleOCR는 책등의 잔글씨까지 다 읽어 준다. 제목만 골라내는 규칙을 다시 맞춰야 한다
  (`탄탄수학동화 품화 수서누가먼저 먹어야 할까/여원어` 처럼 나온다)

### 같은 모델을 감싼 JS 패키지들

[paddleocr.js](https://github.com/X3ZvaWQ/paddleocr.js),
[ppu-paddle-ocr](https://github.com/PT-Perkasa-Pilar-Utama/ppu-paddle-ocr),
[@paddleocr/paddleocr-js](https://www.npmjs.com/package/@paddleocr/paddleocr-js),
[paddleocr-browser](https://github.com/xulihang/paddleocr-browser) 등이 있다.
전부 같은 PP-OCR 모델을 onnxruntime-web으로 돌리는 포장이다. 우리는 책등을 이미
직접 자르므로 검출 모델이 필요 없고, 인식 모델 하나만 쓰면 된다. 포장을 쓸 이유가 적다.

### transformers.js + 한국어 TrOCR — 현실성 없음

[ddobokki/ko-trocr](https://huggingface.co/ddobokki/ko-trocr) 같은 한국어 TrOCR가 있고
[transformers.js](https://huggingface.co/docs/transformers.js/en/index)로 브라우저에서 돌릴 수 있다.
다만 인코더+디코더 구조라 모델이 수백 MB이고 한 줄에 수 초가 걸린다. 한 칸에 46권이면 못 쓴다.

### 파이썬 전용 — 브라우저 불가

Surya, docTR, EasyOCR, MMOCR 은 서버가 있어야 한다. 이 앱은 정적 페이지다.

### 브라우저 기본 API — 해당 없음

Chrome의 Shape Detection `TextDetector` 는 글자 **위치만** 찾고 내용을 읽지 않는다.
게다가 데스크톱에서는 기본으로 꺼져 있다.

## 3. 클라우드 OCR

| | 한국어 | 걸림돌 |
| --- | --- | --- |
| [네이버 CLOVA OCR](https://www.ncloud.com/product/aiService/ocr) | 국내 서비스 중 가장 강한 축 | 키, 사진 전송, 종량 과금 |
| Upstage Document AI | 한국어 강함 | 위와 같음 |
| [Google Vision](https://docs.cloud.google.com/vision/docs/detecting-text) | 속도는 빠르나 한글은 국내 서비스보다 약한 편 | 위와 같음 |
| Azure / AWS | 한글 특화 아님 | 위와 같음 |

정확도는 가장 확실하다. 그런데 **키가 필요하고 사진이 기기 밖으로 나간다.**
지금 화면에 "사진은 기기 밖으로 나가지 않습니다"라고 적어 둔 것과 정면으로 어긋난다.
집 책장 사진이라 더 그렇다. 쓰려면 그 약속부터 바꿔야 한다.

## 4. 멀티모달 모델(VLM)에 사진째로 묻기

Claude·GPT·Gemini의 비전 모델에 책장 사진을 통째로 넣고 "책 제목을 왼쪽부터 적어라"
라고 시키는 방법. 한 번 호출로 끝나고 문맥으로 오탈자를 스스로 고친다.
단점은 클라우드와 같다 — 키, 사진 전송, 비용. 그리고 권수와 순서를 모델이 지어낼 수 있어,
"실제 책장을 그대로 옮긴다"는 이 앱의 뼈대와 잘 맞지 않는다.

## 5. 인식 뒤에 고치는 방법 — 몫이 작다

- **퍼지 제목 검색**: `비슷은 함` 구간을 책 DB로 복구하는 안. 하나씩 뜯어보니 정말 정답에
  가까운 것은 5권뿐이고 나머지는 다른 책 글자와 우연히 닮아 잡힌 가짜였다. 몫이 작다
- **사용자 교정 학습**: 고친 제목을 쌓아 두고 다음 촬영 때 맞춰 본다. 키·네트워크가 필요 없지만
  같은 책장을 다시 찍을 때만 듣고, 첫 촬영은 그대로다

## 권고

**PaddleOCR 한국어를 브라우저에서 쓰는 쪽**이 유일하게 재서 이긴 길이다.
키도 없고 사진도 기기 밖으로 나가지 않아 지금 앱의 약속을 그대로 지킨다.
값은 첫 실행 다운로드 약 23MB와 인식 코드 교체다.

아직 재지 않은 것:
- 46권을 이어서 돌릴 때의 실제 시간과 휴대폰 메모리
- 합성 벤치(`bench/run.mjs`)에서의 성적. 영문 책장이 지금보다 나빠지지 않는지
- PaddleOCR 출력에서 제목만 골라내는 규칙

## 직접 재보기

```bash
npm run fetch:ppocr                                  # 모델 12.8MB + 런타임 받기 (한 번)
npm run dev                                          # 다른 터미널에서
node bench/crops.mjs 사진.jpg /tmp/bands 0 60          # 책등별로 잘라 두고
node bench/ppocr.mjs /tmp/bands/*-up.png --list > pp.txt
node bench/read.mjs 사진.jpg > tess.txt                # 비교군
node bench/score.mjs 정답.txt tess.txt pp.txt          # 같은 잣대로 채점
```

`정답.txt` 는 책장에 꽂힌 순서대로 제목을 한 줄씩 적은 파일이다.
모델과 런타임은 저장소에 넣지 않는다 (`public/ppocr`, `public/ort` 는 gitignore).
