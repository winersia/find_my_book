# 책장 스캐너 (find_my_book)

**내 책장을 앱 안에 그대로 옮긴다.** 실제 책장과 같은 칸 수로 맞춰 두고, 칸마다 사진을 찍으면
그 칸에 꽂힌 책이 실제 순서 그대로 앱 책장에 들어선다. 책을 옮기거나 빼면 앱에서도 옮기고 뺀다.

인식은 오픈소스 OCR인 [tesseract.js](https://github.com/naptha/tesseract.js)로
**브라우저 안에서** 처리합니다. 서버도, API 키도, 사진 업로드도 없습니다.

자세한 시나리오와 완료 기준은 [docs/시나리오.md](docs/시나리오.md)에 있습니다.

## 화면 흐름

1. **책장 설정** — 왼쪽에서 가로·세로 칸 수를 조절하면 오른쪽 미리보기가 바로 따라 바뀝니다.
   기본은 가로 8 × 세로 2입니다. 실제 책장과 같은 칸 수로 맞춰 주세요.
2. **책장 화면** — 만든 책장이 늘 보입니다. 칸에 꽂힌 책은 사진에서 뽑은 색과 두께로 그려져
   실제 책장과 닮아 보입니다.
3. **칸 채우기** — 칸을 누르고 [이 칸 촬영하기]로 그 칸만 찍습니다. 인식이 끝나면 왼쪽부터의
   순서 그대로 보여 주고, [이 칸에 넣기]를 누르면 그 칸이 채워집니다.
4. **손보기** — 제목·저자 고치기, 순서 바꾸기(← →), 빼기(×), 책 추가, 다른 칸으로 옮기기.
   같은 칸을 다시 찍으면 내용이 교체됩니다.
5. **여러 책장** — 거실·서재처럼 책장을 여러 개 두고 위쪽에서 전환합니다.

모든 변경은 즉시 브라우저에 저장되고, CSV로 내보내면 어느 칸 몇 번째 책인지까지 남습니다.

## 실행

```bash
npm install
npm run dev      # http://localhost:5173
```

빌드해서 아무 정적 호스팅에나 올려도 됩니다. 백엔드가 필요 없습니다.

```bash
npm run build
npm run preview
```

### 완전 오프라인으로 쓰기

기본값에서는 언어 데이터만 처음 한 번 공개 CDN에서 받아 옵니다.
영어 2.8MB, 한국어 1.5MB, 세로 한글 0.6MB이고, 쓰는 언어의 것만 받습니다.
그것마저 없애려면 미리 받아 두고 경로를 바꿔 주세요.

```bash
npm run fetch:langdata            # public/tessdata 에 eng, kor 저장
VITE_TESSDATA_PATH=/tessdata npm run build
```

OCR 워커와 wasm 코어는 이미 앱과 함께 배포됩니다. `npm install` 뒤 빌드할 때
`scripts/copy-tesseract-assets.mjs`가 `public/tesseract`로 복사합니다.

언어 데이터를 못 받으면(오프라인이거나 CDN이 막힌 경우) 화면에 그 사실과 함께
위 명령을 안내합니다. 기다리다 멈춰 있지 않습니다.

### 휴대폰에서 카메라 쓰기

브라우저는 `localhost`가 아닌 주소에서 **HTTPS일 때만** 카메라를 열어 줍니다.
휴대폰에서 테스트하려면 터널로 HTTPS 주소를 만들어 접속하세요.
카메라를 못 여는 환경에서는 **사진 선택** 버튼으로 갤러리 사진을 씁니다.

## 어떻게 읽는가

사진 한 장을 통째로 OCR에 넣으면 옆 책 글자가 한 줄로 섞여 읽힙니다.
그래서 책등을 먼저 나눈 뒤 한 권씩 읽습니다.

1. **기울기 추정** — 에지를 여러 각도로 기울여 투영해 가장 날카로운 각도를 찾습니다.
   손으로 찍은 사진은 대개 몇 도씩 기울어 있고, 그대로 두면 경계가 끊겨 보입니다.
2. **책등 분할** — 두 가지 단서를 섞어 씁니다.
   하나는 기울기를 따라 내려가며 잰 "가장 긴 연속 세로 에지"입니다. 책 경계는 위아래로
   길게 이어지고 글자 획은 짧게 끊깁니다. 다른 하나는 열마다의 대표 색이 바뀌는 자리로,
   밝기가 비슷한 두 책(파랑 옆 초록)을 갈라 줍니다. 대표 색은 평균이 아니라 중앙값을
   씁니다. 평균을 쓰면 큰 글자가 지나가는 열이 통째로 밝아져 가짜 경계가 생깁니다.
3. **넓은 구간 쪼개기** — 한 책장에 꽂힌 책은 두께가 비슷합니다. 다른 구간보다 유난히
   넓으면 경계를 놓친 것으로 보고 안쪽에서 가장 그럴듯한 자리를 찾아 나눕니다.
   전역 임계값을 낮추는 대신 이렇게 국소적으로만 완화합니다.
4. **세로 구간 잘라내기** — 밴드마다 책이 실제 차지하는 위아래 범위를 찾아 자릅니다.
   위쪽 배경이 섞여 들어가면 OCR이 아무것도 못 읽고 통째로 실패합니다.
5. **세 가지로 읽기** — 돌려 세운 두 방향(위→아래, 아래→위)으로 읽습니다.
   결과가 시원찮으면 한국 책에 흔한 **세로로 쌓은 글자**를 의심해, 돌리지 않은 크롭을
   세로 전용 모델(`kor_vert`)로 한 번 더 읽습니다. 잘 읽힌 책등은 건너뛰므로
   영문 책장에서는 시간이 늘지 않습니다.
6. **읽기 고르기** — 페이지 전체 신뢰도는 거꾸로 읽은 글자에도 높게 나와 못 믿습니다.
   글자 수로 가중한 단어 신뢰도에 기호 범벅과 짧은 결과를 깎아 고릅니다. 이때 한글 음절은
   자모 두세 개가 모인 글자라 라틴 한 글자보다 무겁게 셉니다. 같은 무게로 세면
   "코스모스"(네 글자)가 길기만 한 영문 오독에 늘 집니다.
   진 후보들도 남겨 두어, 화면에서 "다르게 읽기"를 눌러 바꿔 끼울 수 있습니다.
7. **다듬기** — 한글이 대부분인 읽기에서는 옆 책에서 넘어온 라틴 문자 쪼가리를 버리고,
   세로로 읽어 음절이 떨어져 나온 결과("코 스 모 스")는 붙입니다.
8. **제목 보정** — Open Library에서 찾아 정식 제목과 표지를 붙입니다. 오탈자 교정도 겸합니다.
   네트워크가 막혀 있으면 이 단계만 조용히 건너뜁니다.

책등을 나누지 못하면 사진 전체를 세 방향으로 읽어 줄 단위로 건지는 방식으로 물러섭니다.

## 정확도

합성 책장 사진으로 잰 값입니다. `bench/`에 측정 코드가 들어 있어 그대로 재현할 수 있습니다.
실제 사진을 쓸 수 없어 조건을 통제한 이미지(1.2도 기울임, 사진처럼 흐리게 처리, 명암 불균일)를
만들어 씁니다. 실제 사진은 이보다 조건이 나쁩니다.

두 가지를 따로 셉니다. **바로**는 화면에 처음 뜨는 제목이 맞은 권수,
**후보 포함**은 "다르게 읽기"를 한 번 눌러 도달할 수 있는 것까지 셈한 권수입니다.

| 책장 | 바로 (전 → 후) | 후보 포함 (전 → 후) |
| --- | --- | --- |
| 영문 · 돌린 글자 (10권) | 6 → **9** | 9 → **10** |
| 한글 · 돌린 글자 (10권) | 6 → **7** | 8 → 8 |
| 한글 · 세로로 쌓은 글자 (8권) | 0 → **4** | 0 → **6** |

한글 책등에 흔한 세로로 쌓은 글자가 통째로 안 읽히던 것이 가장 큰 구멍이었습니다.
가로용 `kor` 모델로는 거의 못 읽고, 세로 전용 `kor_vert` 모델을 따로 붙여야 읽힙니다.
나머지 개선은 대부분 분할과 후보 고르기에서 나왔습니다.

```bash
npm run dev                                   # 한 터미널에서
node bench/run.mjs                            # 다른 터미널에서
node bench/run.mjs --case ko-stacked          # 한 가지만
node bench/segment.mjs bench/.cache/ko-stacked.png   # 책등 분할만 눈으로 확인
```

`bench/flow.mjs`는 정확도가 아니라 **시나리오대로 도는지**를 봅니다.
`docs/시나리오.md`의 완료 기준을 그대로 확인합니다. Chromium의 가짜 카메라에 합성 책장
영상을 물려, 책장 설정부터 칸 선택, 촬영, 순서 반영, 순서 바꾸기, 다시 찍기, 칸 수 바꾸기,
책장 추가, 새로고침 후 유지까지 실제로 조작합니다 (15가지).

```bash
npm run build && npm run preview              # 한 터미널에서
node bench/flow.mjs                           # 다른 터미널에서 (15가지 점검)
```

남은 한계:

- 짧은 제목("총 균 쇠")이나 좁은 책등은 아직 놓칩니다.
- 두께가 비슷한 책이 이어지면 경계를 잘못 잡아 두 제목이 한 줄로 섞일 때가 있습니다.
- 글자가 작거나 가려진 책등, 반사가 심한 표지는 놓칩니다.
- Open Library는 한국어 도서 수록이 고르지 않아 표지가 안 붙는 책이 많습니다.
- 정확도 수치는 모두 합성 사진 기준입니다. 실제 사진으로는 재 보지 않았습니다.
- 실제 휴대폰 카메라로도 확인하지 않았습니다. 위 점검은 가짜 카메라 장치를 씁니다.

### 잘 찍는 요령

- 책장 한 칸이 화면에 꽉 차게, 정면에서 찍습니다. 멀리서 전체를 담으면 글자가 뭉갭니다.
- 책등에 그림자나 반사가 생기지 않게 합니다.
- 넓은 책장은 칸별로 나눠 찍은 뒤 한 번에 읽는 편이 정확합니다.

## 성능

한 권마다 두 방향을 읽으므로 책 수에 비례해 시간이 듭니다. 데스크톱에서는 열 권 남짓에
수십 초, 휴대폰에서는 그보다 더 걸립니다. 언어 데이터는 처음 한 번만 받아 캐시합니다.
"영어만"으로 두면 눈에 띄게 빨라집니다.

## 구조

```
docs/시나리오.md     사용자 시나리오와 완료 기준
src/lib/bookcase.ts  책장·칸·책 자료 구조와 편집 연산, 저장, 내보내기
src/lib/segment.ts   기울기 추정, 책등 분할, 크롭 생성 (가로/세로 세 가지), 책등 색 뽑기
src/lib/ocr.ts       tesseract 워커 관리, 세 방향 인식, 읽기 선택, 텍스트 정리
src/lib/enrich.ts    Open Library 조회 (실패해도 무시)
src/components/      책장 설정, 책장 그림, 칸 편집, 촬영 시트, 카메라
scripts/             tesseract 자산 복사, 언어 데이터 내려받기
bench/               정확도 재기, 책등 분할 보기, 시나리오 완료 기준 점검
```
