# 책장 스캐너 (find_my_book)

**내 책장을 앱 안에 그대로 옮긴다.** 실제 책장과 같은 칸 수로 맞춰 두고, 칸마다 사진을 찍으면
그 칸에 꽂힌 책이 실제 순서 그대로 앱 책장에 들어선다. 책을 옮기거나 빼면 앱에서도 옮기고 뺀다.

- 사이트: https://winersia.github.io/find_my_book/
- 지금 버전: 0.9.0 ([CHANGELOG.md](CHANGELOG.md)). 앱의 "책장 설정과 내보내기" 맨 아래에도 보입니다.

인식은 오픈소스 OCR인 [PaddleOCR PP-OCRv5](https://huggingface.co/PaddlePaddle/korean_PP-OCRv5_mobile_rec_onnx)
한국어 모델을 [onnxruntime-web](https://onnxruntime.ai/docs/tutorials/web/)으로 돌려
**브라우저 안에서** 처리합니다. 서버도, API 키도, 사진 업로드도 없습니다.

## 화면 흐름

1. **책장 설정** — 흔한 책장 종류(3단·5단 책장, 와이드 책장, 큐브 수납장)에서 고르면 칸 수와 칸 크기가
   채워집니다. 다르면 숫자를 고치고, 없으면 직접 맞춥니다 (기본 8 × 2, 칸 40×30cm).
   그리고 **꽂힌 책의 두께**(얇은 책 위주 · 보통 · 섞임)를 꼭 고릅니다. 칸 너비와 책 두께로 한 칸에 몇
   권쯤인지 어림해 **몇 번에 나눠 찍을지 미리 알려 줍니다** (한 장에 30권 안팎).
   예: 5단 책장(칸 76cm)에 그림책이면 약 68권 → 3번에 나눠.
2. **책장 화면** — 만든 책장이 늘 보입니다. 칸에 꽂힌 책은 사진에서 뽑은 색과 두께로 그려집니다.
3. **칸 채우기** — 칸을 누르고 [이 칸 촬영하기]로 그 칸만 찍습니다. 카메라를 못 쓰면 [사진 고르기].
   긴 칸은 "1/2번째 사진 — 칸의 왼쪽 절반을 화면에 꽉 채워 주세요"처럼 장마다 칸의 어디를 찍을지
   안내하고, 남은 장을 [오른쪽 절반 이어서 찍기 (2/2)]로 먼저 권합니다. 그 밖에도 한 칸이 한 장에
   안 들어오면 [이어서 찍기]로 나눠 찍습니다.
4. **결과 확인** — 왼쪽부터의 순서 그대로 제목이 채워져 나옵니다. **확신이 92% 미만이거나 제목을
   못 읽은 책은 하나씩 확인해야** [n권 이 칸에 넣기]가 나옵니다. 그 전에는
   "확인 n권 남음 · 다음 책 보기"가 다음 확인할 책으로 데려갑니다.
   - 확인할 책에는 인식기가 실제로 읽은 책등 그림이 붙습니다. 견줘 보고 [맞아요], 고쳐 쓰기, [빼기].
   - 확인하거나 고친 제목은 기억해 두었다가, 같은 책을 다시 찍으면 채웁니다 ("기억한 제목" 표시).
5. **손보기** — 제목·저자 고치기, 순서 바꾸기, 빼기, 책 추가, 다른 칸으로 옮기기, 다시 찍기.
   빼기·비우기·교체는 **되돌리기**가 딸려 옵니다.
6. **여러 책장** — 거실·서재처럼 책장을 여러 개 두고 위쪽에서 전환합니다.

모든 변경은 즉시 이 기기의 브라우저(localStorage)에 저장됩니다. CSV·JSON 으로 내보내면 어느 칸
몇 번째 책인지까지 남습니다. 기억한 제목은 "책장 설정과 내보내기"의 [기억한 제목 지우기]로 지웁니다.

## 실행

```bash
npm install
npm run dev      # http://localhost:5173
```

```bash
npm run build    # dist/ 에 정적 파일
npm run preview  # http://localhost:4173
```

`npm run dev` 와 `npm run build` 는 먼저 `scripts/fetch-ppocr.mjs` 를 돌려 인식 모델(Hugging Face)과
onnxruntime 런타임을 `public/ppocr`, `public/ort` 에 받아 둡니다. 이미 받아 뒀으면 건너뜁니다.

### 인식 모델 내려받기

모델은 앱과 같은 곳에서 함께 배포되므로 다른 CDN 에 기대지 않습니다. 사용자는 처음 한 번만
모델 약 17MB(검출 4.8MB, 인식 13.4MB)와 onnxruntime 런타임을 받고, 그 뒤로는 브라우저가 캐시합니다.

이 내려받기는 **앱을 열자마자 뒤에서 시작합니다.** 첫 화면은 기다리지 않고 바로 그려지고, 헤더
아래 얇은 띠가 `글자 인식 준비 중 · 3.4 / 17.4MB` 처럼 받은 양을 보여 줍니다. 띠는 아무것도
막지 않아 받는 동안에도 책장을 만들고 칸을 고를 수 있고, 끝나면 스스로 사라집니다. 캐시가 살아
있는 재방문처럼 금방 끝나면 띠를 띄우지 않습니다. 데이터 절약 모드에서는 셔터를 누를 때 받습니다.
못 받으면 띠에 그 사실과 [다시 시도]가 남습니다.

진행률의 분모는 `src/lib/ppocr.ts` 의 `MODEL_BYTES` 입니다. 서버가 gzip 으로 보내면
`content-length` 가 압축된 크기라 못 쓰기 때문에 배포하는 파일 크기를 상수로 두고,
`scripts/fetch-ppocr.mjs` 가 실제 파일과 맞는지 확인합니다. 모델을 바꾸면 거기서 멈춥니다.

## 배포

서버가 필요 없습니다. 빌드 결과물(`dist`, 약 32MB 중 대부분이 모델과 wasm)만 올리면 됩니다.

### GitHub Pages (설정돼 있음)

`main` 에 올라오면 `.github/workflows/deploy.yml` 이 빌드해서 배포합니다.
저장소 Settings → Pages → Source 가 **GitHub Actions** 여야 합니다.

주소는 `https://<사용자>.github.io/<저장소 이름>/` 입니다. 하위 경로라 자산 경로가 어긋나기 쉬운데,
워크플로가 저장소 이름을 `VITE_BASE` 로 넣어 줍니다.

### 다른 곳에 올릴 때

Cloudflare Pages, Netlify, Vercel 모두 됩니다. 빌드 명령은 `npm run build`, 배포할 폴더는 `dist`.
최상위 도메인이면 `VITE_BASE` 는 그대로 두고, 하위 경로라면 넣고 빌드하세요.

```bash
VITE_BASE=/find_my_book/ npm run build   # 하위 경로에 올릴 때
npx vite preview --base=/find_my_book/   # 같은 경로로 확인
```

### 휴대폰에서 카메라 쓰기

브라우저는 `localhost`가 아닌 주소에서 **HTTPS일 때만** 카메라를 열어 줍니다.
GitHub Pages 는 HTTPS 라 그대로 됩니다. 로컬 개발 서버를 휴대폰으로 열려면 터널로 HTTPS 주소를
만들어 접속하세요. 카메라를 못 여는 환경에서는 [사진 고르기]로 갤러리 사진을 씁니다.

## 어떻게 읽는가

사진 한 장을 통째로 OCR 에 넣으면 옆 책 글자가 한 줄로 섞여 읽힙니다. 그래서 **글자 줄**을 먼저
찾아 줄마다 읽고, 줄들을 책등 경계로 묶어 책 한 권으로 만듭니다 (`src/lib/ocr.ts` 의 `readShelf`).

1. **글자 찾기** — 사진 전체(긴 변 2560px)를 검출 모델에 넣어 "여기가 글자다" 확률 지도를 얻습니다.
2. **글자 줄 뽑기** — 지도에서 덩어리마다 기울기(주성분)를 재어 기운 그대로 줄을 잘라냅니다.
   원근 때문에 왼쪽 책과 오른쪽 책이 서로 다르게 기울기 때문입니다 (`lines.ts`).
3. **줄 읽기** — 줄을 돌려 세운 두 방향(위→아래, 아래→위)으로 읽고 점수가 높은 쪽을 씁니다.
   앞의 네 줄로 방향이 정해지면 나머지는 그 방향만 읽고, 잘 안 읽히는 줄(거꾸로 꽂힌 책)만 반대도 봅니다.
   - **세로로 쌓은 글자**는 음절을 하나씩 떼어 똑바로 세운 채 가로로 늘어놓은 것도 읽어 점수로 고릅니다.
   - 확신이 85% 미만인 줄은 위아래를 바짝 잘라 한 번 더 읽습니다. 이 인식기는 글자가 줄 높이를
     꽉 채울 때 잘 읽습니다.
   - 후보는 확신도와 글자 수를 함께 봐서 고릅니다. 확신만 보면 짧게 읽은 쪽이 이깁니다.
4. **책으로 묶기** — 이웃한 두 줄 사이에 위아래로 길게 이어진 책등 경계가 없으면 같은 책입니다.
   두 책 사이에 경계가 더 있고 색이 양옆과 다르면 **글자 없는 책**으로 자리를 하나 넣습니다.
   빠뜨리면 뒤 책들이 한 칸씩 당겨집니다. 너무 얇거나(휜 책등의 옆면) 너무 넓으면(드러난 표지) 넣지 않습니다.
5. **제목 고르기** — 책 한 권에 줄이 여럿이면 제목을 고릅니다.
   - 책등 위아래 끝의 시리즈·출판사 라벨은 제목이 될 수 없습니다 (선반 높이의 위 22%·아래 15%).
     그런 라벨만 있는 묶음은 이웃 책에서 떨어져 나온 것이라 책으로 세지 않습니다.
   - 여러 책등에 되풀이되는 글자는 시리즈 이름, "그림·옮김·지음"이 든 줄은 저자 줄이라 뒤로 뺍니다.
   - 남은 줄 중 굵고 또렷한 줄이 제목입니다. 같은 축 위에 바로 이어진 줄은 제목 뒷부분으로 잇습니다.
6. **기억한 제목 채우기** — 확인이 필요한 책 가운데, 예전에 사용자가 고친 책과 읽은 글자·책등 무늬가
   닮은 것은 그 제목으로 채웁니다 (`memory.ts`). 둘 다 맞으면 확인 없이 넘기고, 하나만 맞으면 확인을 받습니다.
7. **책 정보 붙이기** — 결과를 보여 준 뒤 뒤에서 Open Library 를 찾아 정식 제목·표지·ISBN 을 붙입니다.
   네트워크가 막혀 있으면 조용히 건너뜁니다.

글자 줄을 두 개도 못 찾으면 책등을 색·경계로 먼저 나눠 한 권씩 읽는 예전 방식(`segment.ts`)으로
물러서고, 그것도 안 되면 사진 전체를 읽어 줄 단위로 건집니다. 책장 그림에 쓰는 책등 색도 `segment.ts` 가 뽑습니다.

인식은 onnxruntime 의 워커에서 돌고, 단계 사이와 줄마다 화면을 그립니다. 그래도 잠깐 멈추는 동안에는
로딩 표시가 CSS 애니메이션으로 돌아 앱이 죽은 것처럼 보이지 않습니다.

## 정확도

### 실제 사진

실제 책장 사진 한 장(2576×1932, 그림책 29권)으로 잰 값입니다 (v0.7.0).

| | 권수 |
| --- | --- |
| 맞게 읽음 (제목 90% 이상 일치) | 19 |
| 틀리게 읽음 · 확인 대상 | 9 |
| 글자 없는 책 · 빈칸으로 확인 대상 | 1 |
| 없는 책을 셈 · 확인 대상 | 1 |
| **틀렸는데 확인 없이 들어감** | **0** |

30권 중 15권이 확인 대상이었고, 확인한 제목은 기억해 두어 같은 책장을 다시 찍으면 2권만 묻습니다.
없는 책으로 센 한 자리를 [빼기] 하면 29권 순서가 모두 맞습니다. 개인 사진이라 저장소에 넣지 않았습니다.
자세한 내용은 [docs/인식률-개선.md](docs/인식률-개선.md).

### 합성 사진

조건을 통제한 이미지(1.2도 기울임, 사진처럼 흐리게, 명암 불균일)를 만들어 잽니다.
**바로**는 처음 뜨는 제목이 맞은 권수, **후보 포함**은 "다르게 읽기"까지 셈한 권수,
**글자까지 정확**은 한 글자도 틀리지 않은 권수입니다.

| 책장 | 바로 | 후보 포함 | 글자까지 정확 |
| --- | --- | --- | --- |
| 영문 · 돌린 글자 (10권) | 9 | 9 | 8 |
| 한글 · 돌린 글자 (10권) | 9 | 9 | 9 |
| 한글 · 세로로 쌓은 글자 (8권) | 8 | 8 | 8 |

### 재는 도구

`bench/` 의 도구는 앱과 똑같은 코드로 읽습니다. 정확도 도구는 개발 서버(`npm run dev`), 화면 도구는
빌드한 앱(`npm run build && npm run preview`)을 띄워 두고 다른 터미널에서 돌립니다.

```bash
# 정확도 (개발 서버)
node bench/run.mjs                            # 합성 책장 세 가지
node bench/read.mjs ~/사진.jpg > 결과.txt     # 실제 사진을 읽어 결과만 출력
node bench/order.mjs 정답.txt 결과.txt        # 왼쪽부터 자리별 채점 (순서·권수까지)
node bench/groups.mjs ~/사진.jpg              # 줄을 책으로 어떻게 묶었는지 색칠한 그림
node bench/linecrops.mjs ~/사진.jpg 폴더 x0 x1  # 잘라낸 글자 줄을 파일로

# 화면 (빌드한 앱)
node bench/flow.mjs                           # 시나리오 완료 기준 23가지 + 누름 횟수
node bench/longshelf.mjs                      # 책장 템플릿·책 두께와 나눠 찍기 안내 16가지
node bench/review.mjs ~/사진.jpg              # 결과 확인 단계와 기억한 제목 8가지
node bench/memory.mjs ~/사진.jpg              # 다시 찍은 것처럼 바꾼 사진으로 기억 알아보기
node bench/mobile.mjs ~/사진.jpg              # CPU 4배 감속에서 화면이 멈추는 구간과 로딩 표시
node bench/copy.mjs --verbose                 # 화면에 적힌 설명 글자 수
```

`flow.mjs` 는 Chromium 의 가짜 카메라에 합성 책장 영상을 물려 휴대폰 폭에서 책장 설정부터 촬영, 결과
확인, 순서 바꾸기, 다시 찍기, 칸 수 바꾸기, 새로고침 후 유지까지 실제로 조작합니다
([docs/시나리오.md](docs/시나리오.md) 의 완료 기준). Open Library 가 닿지 않는 곳에서는
`FLOW_FAKE_OPENLIBRARY=1` 로 응답을 흉내 냅니다.

## 잘 찍는 요령

- **한 칸이 화면에 꽉 차는 가장 먼 거리에서, 정면으로 한 장.** 실측에서 가장 좋았습니다. 더 가까이
  가서 얻는 화소는 원근 손해를 넘지 못했습니다 ([docs/측정-기록.md](docs/측정-기록.md)).
- 방향은 칸 모양에 맞추면 됩니다. 책 높이가 프레임 높이에 다 들어와야 합니다.
- 책등 하나가 사진에서 40px 은 되어야 합니다. 앱이 카메라 해상도로 "한 번에 n권까지"를 계산해
  알려 주고, 찍은 뒤 책등이 그보다 얇으면 알려 줍니다.
- **책장 설정에서 책장 종류와 책 두께를 실제대로 골라 주세요.** 앱이 한 칸에 몇 권쯤인지 어림해 몇 번에
  나눠 찍을지 정하고, 장마다 칸의 어디를 찍을지 알려 줍니다. 한 장에 담긴 권수가 정확도를 거의 다 정합니다.
- **나눠 찍기는 한 칸이 한 장에 안 들어올 때** 씁니다. [이어서 찍기]로 한두 권만 겹치게 찍으면
  이어 붙고, 이음매에서 제목이 같은 책은 한 권만 남깁니다. 나눠 찍는다고 제목이 더 잘 읽히지는 않습니다.
- 책을 비스듬히 꽂지 않습니다. 드러난 앞표지를 책 한 권으로 잘못 셀 수 있습니다.
- 책등에 그림자나 반사가 생기지 않게 합니다. 그늘에 든 책은 눈에 띄게 덜 읽힙니다.

## 성능

위 실제 사진(30권)을 읽는 데 데스크톱 Chromium 에서 약 20~25초, CPU 를 4배 느리게 건 휴대폰 흉내에서
셔터부터 결과까지 약 26초 걸렸습니다. 읽는 동안 진행 상황(n/줄 수)과 남은 시간이 보이고 언제든
취소할 수 있습니다. 실제 휴대폰에서는 기종에 따라 더 걸릴 수 있습니다.

## 남은 한계

- 장식 글꼴, 아주 작은 글씨, 거칠게 쌓은 글자는 못 읽습니다 ("자연다큐백과 돌고래", "케첩 기차").
  확인 대상으로 뜨고, 한 번 고쳐 주면 다음부터는 기억한 제목으로 채웁니다.
- 숫자가 섞인 쌓은 글자("100층짜리 집")를 엉뚱하게 읽습니다.
- **칸이 넓어 한 장에 많이 담으면 제목이 무너집니다.** 두 배 넓은 칸(58권)을 한 장에 담으면 맞게 읽는
  비율이 66% 에서 52% 로 떨어졌습니다. 그런데도 "한 장에 n권까지" 안내는 76권이라고 해 실제보다 후합니다.
  넓은 칸은 책장 설정에서 책장 종류와 책 두께를 골라 나눠 찍어 주세요. 한 장에 30권 안팎이라는 기준과
  책 두께 어림값(얇은 책 1cm, 보통 2.2cm)도 그림책 사진 한 장으로 정한 값입니다.
- 얇은 책이 두꺼운 책 사이에 섞이면 얇은 책이 뭉개져도 따로 알리지 않고, 글자 없는 아주 두꺼운 책은
  빠뜨립니다. 개선 시나리오는 [docs/시나리오.md](docs/시나리오.md#책-두께가-고르지-않거나-칸이-아주-넓을-때).
- 비스듬히 꽂혀 좁게 드러난 앞표지는 글자 없는 책과 두께로 가를 수 없어 한 권으로 셉니다.
  반대로 글자가 안 보이는 아주 두꺼운 책은 표지로 보고 놓칩니다.
- 확인 문턱 92% 때문에 바르게 읽은 책도 일부 확인을 받습니다 (29권 중 3권).
- **Open Library 는 맞춤법을 고쳐 주지 못합니다.** 제목이 이미 맞을 때 정식 표기와 표지·ISBN 을 붙여
  주는 역할입니다. 한국어 도서는 수록이 고르지 않아 자주 비어 있습니다.
- 실제 사진 수치는 사진 한 장으로만 잰 것입니다. 다른 책장·다른 기종에서는 확인하지 못했습니다.
- 화면 점검은 가짜 카메라 장치로 합니다. 실제 휴대폰 카메라로는 자동 점검하지 않습니다.
